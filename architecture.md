# Мега-Архитектура от Второго участника
Промежуточный слой (Middleware) разработан на языке Python с использованием протокола MCP (Model Context Protocol). Он выступает в роли безопасного изолирующего барьера между LLM-агентами и информационной базой «1С:Предприятие». 

Прямые SQL-запросы к СУБД 1С строго запрещены для обеспечения безопасности данных и сохранения бизнес-логики.

## Общая схема взаимодействия компонентов

```text
[ Пользователь ] 
       │
       ▼ (Естественный язык)
[ LLM-агент ]
       │
       ▼ (Протокол JSON-RPC / MCP-инструменты)
[ Python Middleware (MCP) ] 
       │
       ▼ (Безопасный HTTP-запрос по TLS)
[ HTTP-сервис 1С ]
```

1. **Пользователь**: Формулирует запрос на естественном языке (например, "Выведи остатки товара X").
2. **LLM-агент**: Анализирует запрос, сопоставляет его с доступными MCP-инструментами и формирует структурированный JSON-RPC запрос к промежуточному слою.
3. **Python Middleware**: Валидирует запрос, проверяет права доступа (Auth), преобразует абстрактные параметры в формат, понятный платформе 1С. Также шлюз решает технические несоответствия форматов (например, UUID).
4. **HTTP-сервис 1С**: Опубликованный на стороне 1С стандартный REST/HTTP-сервис, который принимает JSON, выполняет безопасный запрос внутри базы данных через встроенный язык 1С и возвращает результат шлюзу.

## Решение проблемы передачи UUID (Little-Endian vs Big-Endian)

Существует проблема: платформа «1С:Предприятие» внутри своей базы данных хранит уникальные идентификаторы (UUID) в формате **Little-Endian** (в частности, меняется порядок байт в первых трех группах), тогда как LLM-агенты, Python и большинство современных систем используют стандартный формат **Big-Endian** (RFC 4122).

Чтобы не происходило путаницы при поиске объектов (например, документов или контрагентов), **Python Middleware берет на себя роль транслятора**:

1. **При чтении данных из 1С**: HTTP-сервис 1С передает UUID в своем внутреннем представлении. Python-шлюз на лету переставляет байты по схеме Little-Endian -> Big-Endian и отдает LLM-агенту стандартную строку UUID.
2. **При отправке данных в 1С**: LLM-агент передает стандартный UUID. Python-шлюз выполняет обратную перестановку байт (Big-Endian -> Little-Endian) перед тем, как отправить его в HTTP-запрос к 1С.

*Реализация на уровне Python (встроенный алгоритм перестановки индексов строки):*
```python
def swap_uuid_endianness(uuid_str: str) -> str:
    clean = uuid_str.replace("-", "")
    # Перестановка байт в первых трех блоках
    g1 = clean[6:8] + clean[4:6] + clean[2:4] + clean[0:2]
    g2 = clean[10:12] + clean[8:10]
    g3 = clean[14:16] + clean[12:14]
    g4 = clean[16:20]
    g5 = clean[20:32]
    swapped = f"{g1}-{g2}-{g3}-{g4}-{g5}"
    return swapped
```
